# Экспорт подписки VLESS

Python 3.10+. Скрипт `subscription_export.py` получает подписку BLACKTEMPLE
и создаёт **два файла**: массив профилей Xray (`.json`) и автономную страницу
с поиском, копированием ключей и QR-кодами (`.html`).

## Запуск

```powershell
python -m pip install -r requirements-subscription.txt
python subscription_export.py -o output/my-subscription
```

Ссылка запрашивается скрытым вводом, чтобы не сохранять её в истории команд.
Можно передать её аргументом (обязательно в кавычках):

```powershell
python subscription_export.py "https://example.com/sub/YOUR_TOKEN" -o output/my-subscription
```

Результат: `output/my-subscription.json` и `output/my-subscription.html`.
Откройте HTML обычным браузером; интернет для него не нужен. QR генерируются
локально при экспорте и встроены в HTML как SVG. Сторонние сервисы и CDN не используются.
Ссылка «Открыть в клиенте» требует установленного обработчика `vless://`.

## JSON и совместимость

JSON — **массив полных отдельных конфигураций Xray**, по одной на сервер.
В каждой есть локальный SOCKS-вход `127.0.0.1:10808` и VLESS-выход.
Клиент должен поддерживать импорт массива Xray-конфигураций; универсального JSON
для v2rayNG, v2rayN, sing-box, Clash/Mihomo и других клиентов не существует.
Если клиент принимает только один Xray-профиль, импортируйте один объект из массива.
Для запуска через Xray CLI также нужен один объект, а не весь массив; одновременно
запускать эти профили без изменения локальных портов нельзя.
Для sing-box и Clash используйте VLESS URI/QR в клиенте, который умеет их преобразовывать.

Поддержаны TCP/raw (включая HTTP header), WebSocket, gRPC, XHTTP, HTTPUpgrade,
TLS и Reality. Для XHTTP требуется актуальное ядро Xray. Настройки `extra`
сохраняются. Неизвестный транспорт, шифрование или параметр URI вызывает ошибку,
а не молчаливую потерю параметров. В название профиля (`remarks`) добавляются
страна и класс сервера из исходного JSON в начале названия, например `[ГЕРМАНИЯ · TIMEWEB] Сервер`
или `[WHITELIST] Сервер`. Одинаковые страна и класс не дублируются.
Такое же название записывается после `#` в VLESS-ссылке для копирования и QR.
Параметры подключения URI сохраняются без изменений; `fp` — TLS fingerprint,
а не название сервера.
Параметр `allowInsecure`, если он есть в подписке, переносится в TLS-профиль:
не включайте отключение проверки сертификатов без необходимости.

## Подписанный запрос и идентификатор

Использованы результаты `output/subscription-test/REPORT.md` и
`work/fetch_test_subscription.py`: HMAC-SHA256, буквальный UTF-8 ключ,
сообщение `GET\n/sub/{suffix}\n{Unix seconds}\n{installation UUID}`.
Ключ протокола встроен в скрипт: `api_service_enhanced.dart` конечному
пользователю не нужен. При необходимости обновления можно переопределить ключ
через `BLACKTEMPLE_SIGNING_KEY` либо явно указать `--listing`.
Приоритет: окружение → явно указанный листинг → встроенный ключ.
Ключ не выводится в консоль и не попадает в экспорт, но доступен в исходном
коде распространяемого скрипта. Обфускация не обеспечит его секретность.

Готовый файл идентификатора распространять не нужно. При первом сетевом запуске
создаётся собственный постоянный идентификатор пользователя:

- Windows: `%LOCALAPPDATA%/blacktemple-subscription-export/identity.json`;
- macOS: `~/Library/Application Support/blacktemple-subscription-export/identity.json`;
- Linux: `$XDG_CONFIG_HOME/blacktemple-subscription-export/identity.json`
  (по умолчанию `~/.config/blacktemple-subscription-export/identity.json`).

Путь не зависит от расположения скрипта и ссылки подписки. Файл состояния
сохраняется отдельно от двух выходных файлов. Его можно перенести или задать
через `--identity PATH`. Для продолжения прежних тестов **без нового HWID**
укажите `--identity output/subscription-test/identity.private.json` явно:
старый тестовый файл автоматически не используется и не копируется.
**Не удаляйте его между запусками**: новый HWID потенциально может занять слот
устройства. Поведение привязки на сервере неизвестно. Это синтетическая
идентичность по алгоритму тестов, не извлечённые build-поля реального Android-устройства.

Отправляется один HTTPS GET, без повторов и редиректов, с проверкой TLS,
таймаутом 30 секунд (`--timeout`) и лимитом тела 4 MiB. Query-параметры и
fragment в ссылке не допускаются: для них не подтверждён алгоритм подписи.
Запросы к другим API, платежи, смена ключей и VPN-подключения не выполняются.
Ответ-заглушка с loopback/unspecified адресом считается ошибкой.

## Проверка без сети

```powershell
python subscription_export.py --input output/subscription-test/signed-get-second/response.bin -o output/offline-subscription
python -m unittest discover -s tests -p "test_subscription_export.py" -v
```

`--input` принимает сохранённый JSON, обычные VLESS-строки или Base64-подписку;
не создаёт идентификаторов и не выполняет запросов.

Оба выходных файла содержат секреты доступа. Не публикуйте их, не пересылайте
скриншоты QR и не помещайте файлы в публичные каталоги. На Windows доступ
определяется ACL папки: `chmod` не заменяет настройку NTFS-разрешений.
Успешный экспорт не доказывает доступность или работоспособность VPN-серверов.
